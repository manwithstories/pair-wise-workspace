# archivecheck — 历史影像母版恢复验收系统

省级影像档案中心的历史纪录片母版恢复验收工具。纯本地、纯终端、无外部服务依赖，
用于在时钟漂移/回绕、可变帧率、丢包/乱序/重复、损坏帧并存的条件下，
重建统一媒体时间线、生成分片清单，并交叉核验多码率表示层在切换与断点处的对齐。

## 技术栈与依赖

- Go 1.23（`go.mod` 声明，可在 Go 1.23+ 工具链构建）
- `github.com/abema/go-mp4 v1.2.0`：分片与清单的封装级关联
- `github.com/pion/rtp v1.8.9`：RTP 包序号、时间戳与丢包模型
- 标准库 `crypto/sha256`、`encoding/binary`、`testing`

## 架构与数据流

```
输入校验(ingest) → 时间线恢复(clock) → 分片(segment) → 码率扇出(ladder/fanout)
                                          ↓
传输故障模型(transport) → 恢复率/延迟统计        各表示层独立恢复 → 汇合边界核验(ladder/fanin)
```

| 包 | 职责 |
|---|---|
| `internal/model` | 帧元数据、校验结果、分片清单、统计结构 |
| `internal/fixture` | 确定性样本生成（漂移、32 位回绕、VFR、音频采样、损坏注入） |
| `internal/clock` | 时间戳单调扩展解回绕、最小二乘漂移拟合、整数纳秒定点重建、隔离时钟段 |
| `internal/transport` | pion/rtp 包模型、确定性丢包/乱序/重复注入、有界序号窗口 FEC 恢复 |
| `internal/ingest` | 哈希/元数据/倒退/序号校验、首错定位、可信前缀、独立恢复打标 |
| `internal/segment` | 关键帧边界选择、规范化清单哈希、go-mp4 封装关联 |
| `internal/ladder` | 多码率确定性扇出与共享时钟逐边界交叉核验 |
| `internal/checkpoint` | 输入摘要绑定的断点续跑与原子持久化 |
| `internal/pipeline` | 端到端编排、指标汇总、跨模块故障、检查点续跑 |
| `cmd/archivecheck` | 纯终端验收入口 |

### 关键设计约束

- **整数纳秒**：全部媒体时间以 `int64` 纳秒计算；漂移重建采用定点斜率 +
  余数进位，长序列累计截断误差小于 0.02ns，不静默累积。
- **回绕处理**：RFC 3550 半程门限把 32 位时间戳扩展为单调 64 位 tick。
- **隔离段**：时钟突变导致锚点残差超阈值时，突变守卫带标记为隔离时钟段，
  其上的帧只给标称外推时间，禁止作为发布边界。
- **确定性**：样本与清单均为输入参数的纯函数；清单用定长二进制规范化编码后
  取 SHA-256，相同输入和参数重复运行清单哈希完全一致。
- **内存有界**：传输重组与延迟采样均为固定大小窗口。
- **不覆盖输入**：所有产物在内存或独立检查点路径，不回写生成的样本。

## 构建、测试、运行

```bash
go mod tidy
go build ./...
go test ./...
go run ./cmd/archivecheck \
  --frames 12000 --duration 2s --bitrates 360p,720p \
  --drift-ppm 180 --wrap-at 4294960000 \
  --loss-every 97 --corrupt-frame 8111
```

成功路径打印 `sync_error_ms`、`loss_recovery_rate`、`p95_latency_ms`、
`segments`、`boundary_mismatches`、`manifest_sha256`，验收目标：

- 同步误差 ≤ 20ms
- 恢复率 ≥ 95%
- P95 延迟 < 100ms
- 边界不匹配 = 0

程序随后自生成单帧损坏、尾分片截断、漂移突变三类样例，打印错误帧号、
恢复状态与续跑清单哈希；故障路径不发布清单，等效退出码 1。

### 场景模式（`--scenario`）

| 值 | 行为 | 退出码 |
|---|---|---|
| `demo`（默认） | 成功路径 + 三类故障样例 + 续跑一致性 | 0 |
| `corrupt` / `tail` / `drift` | 仅运行对应故障路径，不发布清单 | 1 |
| `resume` | 写入匹配检查点后续跑，打印续跑哈希 | 0 |

退出码：`0` 全部校验通过；`1` 输入或边界校验失败；`2` 参数错误。
注意 `go run` 会把非零退出码统一映射为 1，验证真实退出码请先 `go build` 再运行二进制。

### 检查点续跑

检查点同时固化输入摘要与参数摘要；续跑时重新计算摘要，不匹配则拒绝续跑。
匹配检查点下的续跑清单哈希与无中断运行完全一致。
