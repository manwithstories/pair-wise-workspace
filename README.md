# bcastqc

电视台节目制作中心的入库前 QC 工具：对供应商交付的 MP4/MOV 素材做**无损转封装**，
在尾部截断、局部坏包和不完整索引的批次里快速定位问题、保留可恢复内容，并输出可核对的
JSON 诊断。纯终端运行，不打开窗口、不访问浏览器、不申请摄像头或麦克风。

```console
python3.12 -m venv .venv
.venv/bin/python -m pip install -e '.[test]'
.venv/bin/python -m bcastqc demo --workdir ./.demo --json ./.demo/report.json
.venv/bin/python -m bcastqc verify --report ./.demo/report.json
```

`demo` 会在 `./.demo` 下生成五个本地合成素材（正常、尾部截断、坏包、不完整索引、
不可无损复制），逐一处理后写出 `report.json`；`verify` 重新核对报告里的门槛并给出退出码。

## 退出码

| 码 | 含义 |
| --- | --- |
| 0 | 全部门槛满足 |
| 1 | 门槛未达（或存在只写出部分轨道的素材） |
| 2 | 参数、路径或输入错误（目录不存在、没有可处理素材、体积/轨道超限） |
| 3 | 不可恢复媒体错误（整批素材都无法处理） |

## 验收门槛

报告里的 `thresholds` 与 `verify` 使用同一组常量（`bcastqc.report.THRESHOLDS`）：

| 字段 | 门槛 | 口径 |
| --- | --- | --- |
| `sync_error_ms` | ≤ 20 ms | 仅统计成功写出的素材；对解码后的画面/声音标记实测，而非只看容器时间戳 |
| `recovery_rate` | ≥ 0.80 | 受损素材的均值；分母是声明时长的应有包数 |
| `p95_latency_ms` | ≤ 3000 ms | 10 秒素材的批内 P95 处理时延 |
| `remux_packet_match_rate` | ≥ 0.99 | 输出与保留包逐字节比对，取最小值 |
| `damaged_samples` | ≥ 3 | 被识别并恢复（`recovered`/`partial`）的素材数量 |

`sync_error_ms` 需要素材内置同步标记；`process` 对任意交付目录运行，若目录里没有标记素材，
该项标为 `applicable: false` 并跳过（不判失败）。`damaged_samples` 同理只在 `demo`
（内置三个受损样例）中作为验收项。

## 设计要点

**时间基准统一为有理数。** `timeline.py` 中所有时间都是
`Fraction(pts) * time_base` 秒；`1001/30000` 帧长、`1/90000` 的 MP4 时间基、
`1024/48000` 的 AAC 帧都不经过浮点。间隙/重叠按“包自身时长”推算期望结束时刻，
所以合法的可变帧率间隔不会被误报。

**音画同步靠共享原点，而不是各自归零。** 转封装时对**所有**流减去同一个呈现时刻
（`remux._origin_ticks`）。分别把每路流归零是逐文件脚本产生偏移的根因。
原点取**视频流声明的呈现起点**，而不是最小原始 pts：AAC 编码器前导包常带负时间戳
（本样例为 −21 ms），拿它当原点会把整节目整体后移，且因为两路一起移动，
相对同步检查完全看不出来。以画面起点对齐符合播出习惯（节目从首个画面帧开始计时）；
纯音频素材才退回到最早的声明起点。

输出后再做一次**解码实测**：素材里 1 s / 4 s / 7 s 处同时有 2.5 kHz 短音和 4 帧白闪，
`sync.py` 用频带能量重心与亮度加权中心分别定位，实测误差约 0.014 ms；测试还直接断言
输出标记落在母版位置上（容差 5 ms），专门拦截上述整体位移。拒绝无损复制的素材也会先
测源同步，测不出时给出 `sync_unmeasured` 警告而不是沉默。

**恢复绝不伪造内容。** 每个包要么按原字节写出，要么跳过并计数，从不解码重编码：

- *尾部截断*：把索引声明的每个样本区间与实际存活的字节比对，只保留完全落在文件内的包，
  边界包连同字节偏移记入 `skipped`。
- *局部坏包*：对 H.264/HEVC 检查 AVCC 长度框架、MPEG-4 检查起始码、AAC 检查最小帧头；
  不合格即跳过，邻包不受影响。
- *不完整索引*：索引未覆盖 `mdat` 尾部、或各表互相矛盾时，以索引为准取出可用包，
  丢弃落在 `mdat` 之外的位置项，由封装器按实际写出的包重建一致索引；未引用的字节
  如实上报（`unindexed_bytes`），不臆造。

**写出顺序即依赖顺序。** 轨道图先定输出槽位（视频→音频→其他），每个输出流用源流的
codec template 建立（继承 extradata 与时间基），随后按图写包，容器索引在最后一个包之后
由封装器写出。缺少必需轨道时仍写出剩余轨道，状态为 `partial`、退出码非零。

**逐素材临时文件 + 原子落盘。** 每个素材写到独立临时文件，校验（逐字节比对、解码健康、
同步测量）通过后才 `os.replace` 就位；批次中断只会留下“完整输出或无输出”。

**断点续跑看输入摘要 + 处理策略。** 缓存键是
`sha256(输入文件 SHA-256 + 策略指纹)`；策略指纹包含映射规则、上限、超时、是否解码核对、
同步标记与工具版本。同一输入同一策略直接复用（报告里 `cache: "hit"`），任何策略变化
都会重新处理。`--no-reuse` 可强制重跑。

**资源上限。** 单素材默认上限 2 GiB、64 条轨道；索引只读 box 头与 `moov`，内存随索引而
不是随媒体增长；超时在解复用循环内部检查（每 256 个包），超限即中止且不落盘。

## 模块

| 文件 | 职责 |
| --- | --- |
| `cli.py` | `demo` / `process` / `verify` 子命令与退出码 |
| `pipeline.py` | 单素材流程：探测→恢复→映射→转封装→核验→报告，含原子落盘与缓存 |
| `demux.py` | 只读探测轨道与包；体积/轨道/扩展名校验；无损复制白名单 |
| `container.py` | 纯 Python 的 ISO-BMFF/QuickTime box 解析与索引一致性检查（有界内存） |
| `recover.py` | 截断边界扫描、包结构校验、缺失索引策略与恢复计划 |
| `trackmap.py` | 显式规则到输出轨道图；重复/缺失/类型不符报定位明确的错误 |
| `remux.py` | 字节级包复制、共享原点重基、依赖顺序写出、原子输出 |
| `timeline.py` | 有理数时间线、间隙/回退/重叠、音画漂移判定 |
| `sync.py` | 输出端解码实测音画同步 |
| `report.py` | 逐素材诊断、批次汇总、门槛判定与 JSON 落盘 |
| `fixtures.py` | 确定性合成素材（5 个演示 + 可构造变体） |
| `errors.py` | 可恢复/跳过/致命错误与包级定位信息 |
| `tests/test_pipeline.py` | 真实素材驱动的端到端与单元测试 |

## 测试

```console
.venv/bin/python -m pytest tests/test_pipeline.py -q
```

测试直接驱动 PyAV 与合成夹具，覆盖：VFR 合法的时长保留、时间戳回退与间隙、
重复映射/缺轨/类型不符的定位信息、三类损伤各自的恢复策略、逐字节复制一致性、
重建索引完整性、端到端同步、拒绝组合、原子落盘、缓存命中/失效、部分输出非零退出码、
以及 `python -m bcastqc` 的真实子进程验收。
