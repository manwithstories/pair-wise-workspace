# 镜像格式

## 总布局

镜像按 4 MiB 分块，默认 64 块（256 MiB）。超级块位于块 0，分区表位于物理偏移 4096；所有资产按块对齐。尾部未分配块为零。

超级块字段：

| 偏移 | 长度 | 含义 |
| ---: | ---: | --- |
| 0 | 8 | ASCII 魔数 `FORNSIMG` |
| 8 | 4 | 格式版本，当前为 1 |
| 12 | 4 | 块大小，固定 4 MiB |
| 16 | 4 | 声明总块数 |
| 20 | 4 | 分区数 |
| 24 | 4 | 分区项大小，固定 64 |
| 28 | 4 | 标志 |
| 32 | 8 | 采集时刻，Unix epoch 100ns |

每个分区项 64 字节：

| 偏移 | 长度 | 含义 |
| ---: | ---: | --- |
| 0 | 16 | ASCII 资产名 |
| 16 | 4 | 起始块 |
| 20 | 4 | 占用块数 |
| 24 | 8 | 资产内容长度 |
| 32 | 8 | 资产内逻辑起始偏移 |
| 40 | 4 | 标志 |
| 44 | 20 | 保留 |

资产包括 `SQLITE_MAIN`、`SQLITE_WAL`、`FILE_RECORDS`、`NTP_LOG`、`TZ_RULES`、`MAINTENANCE`。

## 清单

`manifest.jsonl` 每行对应一个 4 MiB 块：

```json
{"block":0,"length":4194304,"offset":0,"prev_hash":"000...","sha256":"..."}
```

清单在镜像注入改写前生成。篡改检测位于物理块层，因此不依赖文件系统时间或 SQLite 页内容解释。

## 文件记录表

`FILE_RECORDS` 开头为 `FILETAB1`、版本、记录数、记录大小，随后为 128 字节记录。每条记录保存 rowid、实体键、UTC 创建/修改时间、本地 naive 创建/修改时间（均为 Unix epoch 100ns）和标志。解析器严格检查表头、版本、记录尺寸和表尾长度。

## 时区与 NTP 资产

`TZ_RULES` 是 UTF-8 JSON，声明基准偏移和有序跳变。程序据此生成最小 TZif v1/v2 数据并调用标准库 `zoneinfo.ZoneInfo.from_file`，避免依赖宿主时区数据库。

`NTP_LOG` 每行一个采样，包含参考 UTC、当时本地时钟、模式（`step`、`drift_start`、`drift_end`、`sample`）和时钟误差秒数。误差定义为本机钟读数对应 UTC 减去参考 UTC；校正值为从临时 UTC 中减去该误差。

`MAINTENANCE` 是已知维护窗口的 JSON。维护窗口和春季 DST 跳变窗口只从“证据空档”结果中扣除，不删除事件。
