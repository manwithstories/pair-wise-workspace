# 取证流程、复核点与限制

## 处理阶段

1. **完整性先行**：逐块计算 SHA-256 并与清单比较，同时复核清单行数、顺序、偏移和 `prev_hash` 链。任何不一致先写入工作库，后续证据解释都继承这一限制。
   镜像读取使用页对齐的滑动 `mmap` 窗口，每个窗口读完后立即关闭，避免 256 MiB 映射页长期驻留。检查点指纹覆盖镜像与清单的实际字节，而不是仅信任文件 mtime。
2. **页级离线恢复**：从主库和 WAL 的原始字节解析页头。WAL 使用累计校验和验证，最后提交点之后的帧全部丢弃。主库 b-tree 提供当前行；freelist 残留和提交过的 WAL 页提供已删行或旧页内容。所有候选按 rowid 去重。
3. **来源分拆**：SQLite 应用日志、文件记录表、元数据告警分别生成 dataclass 事件，避免解析层相互回读镜像。
4. **时间统一**：显式偏移直接转 UTC；naive 时间按镜像时区表定位。春季缺口用转换前偏移，秋季重复时刻用 `fold=0` 的首次出现。随后按 NTP 阶跃/漂移修正本机钟误差。
5. **合流与排序**：同实体键且跨来源相差不超过 2 秒的事件合并，来源列表排序后保留。输出顺序为 UTC、来源优先级、序号和事件 ID。
6. **空档扫描**：以全窗口首个和末个事件为边界，按 epoch 对齐的 300 秒桶统计占用；连续空桶合并后扣除 DST 春季跳变和维护窗口。
7. **报告**：终端和 JSON 都从工作库行数/明细生成，不读取镜像，也不硬编码报告计数。

## 可复核值

- 工作库 `hash_mismatches`：块号、物理偏移、资产、资产内偏移、期望/实际 SHA-256、原因。
- 工作库 `carved_events`：恢复行、来源痕迹、是否来自已删/旧页。
- 工作库 `event_rows`：归一化 UTC、实体键、来源列表、序号、异常标志及原始时间值。
- 工作库 `missing_ranges`：已排除维护与 DST 跳变后的空档。
- `ground_truth.json`：仅用于样本自测的生成参数和预期，不参与报告计数。

## 边界与限制

- 当前样本的损坏是“静默、定长、块内”的；校验能定位到块，但不能仅凭整块哈希还原被改写的原始字节。
- freelist 和 WAL 恢复依赖残留数据仍存在。若介质被安全擦除、VACUUM 或用零覆盖，恢复可能失败。
- 自定义 TZif 只覆盖样本声明年份的规则；真实案件应把镜像内完整时区规则和 NTP 原始记录一并归档。
- 空档表示事件时间线上没有事件桶，不等同于“系统未运行”或“数据被删除”的法律结论。
- 样本中的三处改写用于演示检测与报告链，不能替代实际案件中的双人复核、写保护、封存和证据监管链记录。
